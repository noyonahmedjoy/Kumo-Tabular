# Pre-specified Analysis Plan: OpenML Small-Data Benchmark

Written and committed on 9 November 2026, while the benchmark was running and before any of its results were inspected. The only result seen beforehand was the smoke test on `wdbc` (OpenML 1510), used to verify the pipeline. The analysis code is `scripts/analyze_openml_benchmark.py`, committed with this plan.

## Question

Across a fixed, externally defined set of small, fully numerical tabular datasets, how does Kumo Tabular (`small` checkpoint, default inference settings) compare with seven untuned classical baselines in predictive quality and runtime?

## Datasets (fixed before running)

From OpenML-CC18 (study 99) and OpenML-CTR23 (study 353): all datasets with 150–2,000 rows, at most 60 features, no categorical features, no missing values and, for classification, at most 10 classes. This yields 15 classification and 7 regression datasets (`configs/openml_suite.json`, generated by `scripts/select_openml_suite.py`). No dataset was added or removed after seeing results.

## Splits and seeds

The official OpenML task splits: 10-fold cross-validation, first repetition (repeat 0) for every task, including the four regression tasks that define ten repetitions. The fold index (0–9) is the random seed for every model and for Kumo's generator.

## Models

Kumo Tabular `small` (8 estimators; float32 on the GTX 980M); logistic regression (standardised) or linear regression; random forest and extra trees (500 trees); histogram gradient boosting, XGBoost, LightGBM and CatBoost with library defaults. No model is tuned.

## Metrics

- Primary: log loss (classification), RMSE (regression).
- Secondary, descriptive: accuracy, one-vs-rest macro ROC-AUC and macro-F1 (classification); MAE and R² (regression).
- Each metric is computed per fold and averaged over the 10 folds of a dataset.

## Inference

- Unit of analysis: the dataset. Folds of one dataset share training rows and are not independent; datasets are treated as independent units.
- Global test: Friedman test across all eight models, per task and metric.
- Kumo vs each baseline: two-sided Wilcoxon signed-rank test on the per-dataset means, with Holm correction across the seven baselines. Only the primary metric is used for confirmatory statements. Secondary metrics are reported with the same statistics but are descriptive only.
- Effect sizes: win/tie/loss counts, median absolute and median relative advantage.
- With 7 regression datasets the smallest attainable two-sided Wilcoxon p-value is 2/2^7 = 0.0156, so after Holm correction across seven comparisons no regression comparison can reach 0.05. Regression results are therefore descriptive by design.

## Sensitivity analyses (pre-specified)

1. Excluding `wdbc` (OpenML 1510), which is the Breast Cancer Wisconsin dataset already used in the original two-dataset study.
2. Collapsing related dataset families to one unit each: the NASA software-defect datasets `pc1`, `pc3`, `pc4`, `kc2`, and the `mfeat` datasets `mfeat-morphological`, `mfeat-zernike`.

## Runtime

Median and interquartile range of fit-plus-predict seconds per fold, per model. Kumo runs on the GPU and the baselines on the CPU, so runtimes are reported descriptively and not tested.

## Failure handling

If any model fails on any fold, the analysis stops and the failure is reported. Failed runs are not dropped silently.
